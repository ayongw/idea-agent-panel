## 1. 概述

### 1.1 目标
基于 OpenCode Server 的 C/S 架构，在 IntelliJ Platform 内构建一个 Tool Window 面板，实现对话交互、流式渲染、权限确认和上下文注入的完整闭环。

### 1.2 核心原则
- **纯 Swing 原生 UI**：不使用 JCEF，零额外依赖、全平台兼容、启动开销极低
- **状态与渲染分离**：消息列表管理和事件处理逻辑与 UI 渲染层解耦
- **协议驱动**：以 OpenCode Server 的 HTTP API + SSE 事件流为唯一数据源

### 1.3 技术选型

| 决策点 | 选型 | 理由 |
|--------|------|------|
| 插件语言 | Kotlin | IntelliJ Platform 原生支持，与 IDE API 集成最佳 |
| UI 框架 | Swing + JetBrains UI 组件 | 轻量、无额外依赖、风格与 IDE 完全统一 |
| 富文本渲染 | `JBHtmlPane` + `EditorTextField` | HTML 渲染文本，编辑器组件渲染代码块，保持语法高亮一致 |
| HTTP 客户端 | OkHttp + `okhttp-sse` | OkHttp 官方 SSE 扩展库，完美模拟 SSE 客户端角色 |
| 进程管理 | `OSProcessHandler` | IntelliJ Platform 内置 API，自动处理子进程生命周期和输出流 |
| 流式刷新 | 75ms 批量刷新定时器 | 避免每个 token 触发一次 EDT 更新，防止 UI 卡顿 |

## 3. 核心模块详细设计

### 3.1 进程管理：启动与复用 OpenCode Server

#### 3.1.1 启动流程
```kotlin
// 伪代码
class OpenCodeServerManager : Disposable {
    private var processHandler: OSProcessHandler? = null
    private var serverPort: Int = -1
    private var serverUrl: String = ""
    
    fun start(): CompletableFuture<String> {
        // 1. 分配随机端口
        val port = findFreePort()
        
        // 2. 检查是否已有 Server 运行（健康检查复用）
        if (checkExistingServer(port)) {
            return CompletableFuture.completedFuture(serverUrl)
        }
        
        // 3. 创建命令行
        val commandLine = GeneralCommandLine("opencode", "serve", "--port", port.toString())
        
        // 4. 启动子进程
        processHandler = OSProcessHandler(commandLine)
        processHandler.startNotify()
        
        // 5. 后台线程轮询健康检查
        return waitForHealthCheck(port)
    }
    
    override fun dispose() {
        processHandler?.destroyProcess()
        processHandler?.killProcessTree()  // Windows 文件锁定问题
    }
}
```

#### 3.1.2 关键点
- **端口分配**: `ServerSocket(0).localPort` 动态获取
- **复用策略**: 启动前先检查 `GET /api/info`（v2 健康检查，未就绪返回 503），存活则直接复用
- **就绪检测**: 后台线程轮询 `GET /api/info`，成功后建立 SSE 连接
- **优雅终止**: `dispose()` 中调用 `destroyProcess()` + `killProcessTree()`
- **故障处理**: 启动失败显示错误状态 + 重试按钮 + 手动配置入口

### 3.2 通信层：REST 客户端 + SSE 监听器

#### 3.2.1 REST 端点封装

| 操作 | 端点 | 方法 | 用途 |
|------|------|------|------|
| 健康检查 | `/api/info` | GET | Server 就绪判断、复用检测（未就绪返回 503） |
| 创建会话 | `/api/session` | POST | 新建对话会话 |
| 提交提示 | `/api/session/{id}/prompt` | POST | 发送用户消息 |
| 获取消息 | `/api/session/{id}/message` | GET | 对账权威消息状态 |
| 回复权限 | `/api/session/{id}/permission/{requestID}/reply` | POST | 响应权限请求 |
| 中止执行 | `/api/session/{id}/interrupt` | POST | 取消正在进行的 AI 响应 |

> 实测（opencode v2.0.18）：v1 路径（`/global/health`、`/session`、`/global/event`）会回落到前端 SPA 的 `index.html` 且 HTTP 状态为 200，仅 `/api/*` 是真实接口；`/api/*` 需 HTTP Basic 认证（用户名默认 `opencode`，密码为空则不鉴权）。

#### 3.2.2 SSE 事件监听

```kotlin
class SseEventListener(
    private val serverUrl: String,
    private val onEvent: (OpenCodeEvent) -> Unit
) {
    private var eventSource: EventSource? = null
    
    fun start() {
        ApplicationManager.getApplication().executeOnPooledThread {
            val request = Request.Builder()
                .url("$serverUrl/api/event")
                .build()
            
            eventSource = EventSources.createFactory(okHttpClient)
                .newEventSource(request, object : EventSourceListener() {
                    override fun onEvent(eventSource: EventSource, id: String?, type: String?, data: String) {
                        val event = parseEvent(type, data)
                        // 调度到 EDT 更新 UI
                        SwingUtilities.invokeLater { onEvent(event) }
                    }
                    
                    override fun onClosed(eventSource: EventSource) {
                        // 重连逻辑
                        scheduleReconnect()
                    }
                    
                    override fun onFailure(eventSource: EventSource, t: Throwable, response: Response?) {
                        logError(t)
                        scheduleReconnect()
                    }
                })
        }
    }
    
    fun stop() {
        eventSource?.cancel()
    }
}
```

#### 3.2.3 关键约束
- **SSE 不可单独信任**: 必须定期通过 `GET /api/session/{id}/message` 对账
- **后台线程建立连接**: 使用 `executeOnPooledThread()`
- **UI 更新调度 EDT**: 使用 `SwingUtilities.invokeLater()`
- **自动重连**: 指数退避重连策略

### 3.4 流式渲染策略

#### 3.4.1 设计目标
- 首 token 延迟 < 100ms (感知响应)
- 稳态吞吐: 批量更新避免 EDT 拥堵
- 最终一致性: `text-end` 触发完整渲染

#### 3.4.2 实现方案

```kotlin
class StreamingRenderController {
    // 线程安全缓冲区
    private val textBuffers = ConcurrentHashMap<String, StringBuilder>()
    private val reasoningBuffers = ConcurrentHashMap<String, StringBuilder>()
    
    // 75ms 批量刷新定时器 (EDT 线程)
    private val flushTimer = Timer(75) { flushPendingUpdates() }
    
    fun onTextDelta(messageId: String, delta: String) {
        textBuffers.computeIfAbsent(messageId) { StringBuilder() }.append(delta)
        if (!flushTimer.isRunning) flushTimer.start()
    }
    
    fun onReasoningDelta(messageId: String, delta: String) {
        reasoningBuffers.computeIfAbsent(messageId) { StringBuilder() }.append(delta)
        if (!flushTimer.isRunning) flushTimer.start()
    }
    
    fun onTextStart(messageId: String) {
        // 立即创建 UI 组件，显示占位符
        createMessageBubble(messageId, MessageType.TEXT)
    }
    
    fun onTextEnd(messageId: String) {
        // 最终无损 flush + 完整 Markdown 渲染
        flushTimer.stop()
        val fullText = textBuffers.remove(messageId)?.toString() ?: ""
        renderFinalMarkdown(messageId, fullText)
    }
    
    private fun flushPendingUpdates() {
        // 批量读取缓冲区，更新对应 UI 组件
        textBuffers.forEach { (id, buf) ->
            updateTextBubble(id, buf.toString())
            buf.setLength(0)  // 清空已刷新部分
        }
        reasoningBuffers.forEach { (id, buf) ->
            updateReasoningBubble(id, buf.toString())
            buf.setLength(0)
        }
    }
}
```

#### 3.4.3 替代方案
- IntelliJ `DebouncedUpdates` 工具类
- `javax.swing.Timer` (当前方案，更可控)

### 3.5 上下文注入

#### 3.5.1 注入内容

|------|------|------|

| 显式上下文 | 右键菜单 "Add to Context" | 文件列表 |

#### 3.5.2 实现
```kotlin
class ContextProvider {
    fun collectContext(project: Project, editor: Editor?): PromptContext {
        val context = PromptContext()
        
        // 当前文件
        editor?.let { 
            val file = it.editor?.virtualFile
            file?.let { context.addFile(it.path, it.getSummary()) }
        }
        
        // 选中代码
        editor?.selectionModel?.hasSelection()?.let {
            context.addSelection(editor.selectionModel.selectedText)
        }
        
        // 用户显式添加的文件
        context.addExplicitFiles(ContextManager.getExplicitFiles(project))
        
        return context
    }
}
```

## 4. 关键风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| **SSE 事件丢失** | 权限请求或消息部件遗漏 | 定期 `GET /api/session/{id}/message` 对账；权限请求到达时状态栏通知 |
| **Server 启动失败** | 插件不可用 | 手动配置 Server 地址入口；健康检查 + 指数退避重试 |
| **流式渲染性能** | UI 卡顿 | 75ms 批量刷新 + EDT 调度；大量文本限制渲染窗口 |
| **Windows 进程残留** | 文件锁定导致更新失败 | `dispose()` 中 `killProcessTree()` 确保进程树完全终止 |
| **OpenCode 版本升级** | API 不兼容 | 锁定 SDK 版本；监控 Release Notes；适配层隔离 |
