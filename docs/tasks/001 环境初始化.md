以下是基于 IntelliJ IDEA 2026.2.3 的插件开发前置教程，覆盖从环境准备到项目跑通的完整流程。你当前使用的 IDE 版本已是最新，开发环境无需额外降级或调整。

---

## 一、环境准备

### 1.1 安装 Plugin DevKit

这是开发插件的**必需插件**。从 2023.3 版本起，Plugin DevKit 不再随 IDE 捆绑，必须手动从 JetBrains Marketplace 安装。

**操作路径**：`Settings` → `Plugins` → `Marketplace` → 搜索 `Plugin DevKit` → `Install` → 重启 IDE。

### 1.2 确认 Gradle 插件已启用

IntelliJ IDEA 内置了 Gradle 插件，确保它处于启用状态即可。这是构建插件的推荐方式。

### 1.3 配置 JetBrains Runtime (JBR)

插件开发需要 JetBrains Runtime。2026.2 版本推荐使用 **JBR 25**，你可以在后续项目创建时由 IDE 自动下载，无需提前手动配置。

### 1.4 可选：启用内部模式（便于调试）

在 `Help` → `Edit Custom Properties` 中添加 `idea.is.internal=true`，重启后可以访问内部工具，便于查看插件运行时的内部状态。

### 1.5 可选：安装辅助插件

- **PsiViewer**：查看 PSI 树结构，便于理解代码语义分析。
- **Grammar-Kit**：如果你需要自定义语言支持（OpenCode 插件第一阶段不需要）。

这两个插件均为可选安装。


## 二、创建插件项目

### 2.1 方式一：使用 New Project 向导（推荐）

打开 IntelliJ IDEA 2026.2.3，选择 `File` → `New` → `Project`，在左侧选择 **IntelliJ Platform Plugin**，填写以下信息：

| 字段 | 建议值 |
|---|---|
| **Name** | `opencode-idea-plugin` |
| **Location** | 你选择的项目路径 |
| **Build system** | `Gradle (Kotlin DSL)` |
| **Group** | `com.yourcompany.opencode` |
| **Artifact** | `opencode-idea-plugin` |
| **Version** | `0.1.0` |
| **JDK** | 选择 JBR 25（如未安装，点击 `Download JDK` 让 IDE 自动下载） |

点击 `Create` 后，IDE 会自动生成项目骨架，包含 `build.gradle.kts`、`gradle.properties`、`plugin.xml` 和示例代码。

### 2.2 方式二：使用模块化模板（推荐用于 OpenCode 项目）

考虑到你的 OpenCode 插件需要将**状态管理逻辑**与 **UI 渲染层**解耦（为第二阶段复用做准备），JetBrains 官方的模块化模板是更合适的起点。

```bash
git clone https://github.com/JetBrains/intellij-platform-modular-plugin-template.git
cd intellij-platform-modular-plugin-template
```

该模板将项目拆分为三个模块：

| 模块 | 职责 | 对应 OpenCode 插件的内容 |
|---|---|---|
| **`shared`** | RPC 接口、DTO、序列化器、共享模型 | OpenCode 事件的 DTO、消息部件模型、RPC 契约 |
| **`frontend`** | Tool Window 注册、Swing UI、ViewModel | 对话面板、输入区、思考卡片、权限确认卡片 |
| **`backend`** | 项目级服务、业务逻辑、外部进程访问 | OpenCode Server 进程管理、REST/SSE 客户端、消息状态逻辑 |

模板本身已经包含一个 **Swing 实现的聊天式 Tool Window** 示例，与你的目标场景高度吻合。使用模板后，将示例代码替换为 OpenCode 的集成逻辑即可。


## 三、Gradle 配置详解

### 3.1 核心依赖配置

`build.gradle.kts` 的核心配置如下：

```kotlin
repositories {
    mavenCentral()
    intellijPlatform {
        defaultRepositories()
    }
}

dependencies {
    intellijPlatform {
        intellijIdea("2026.2.3")  // 匹配你的本地 IDE 版本
        // 如果需要 Java PSI 支持（上下文注入需要）
        bundledPlugin("com.intellij.java")
    }
}
```

`intellijIdea("2026.2.3")` 中的版本号应与你本地 IDE 的构建版本一致。你可以在 `Help` → `About` 中查看精确的构建号（如 `2026.2.3`）。

### 3.2 OpenCode 插件所需的额外依赖

除了 IntelliJ Platform SDK，你的插件还需要以下依赖：

```kotlin
dependencies {
    // OkHttp + SSE 扩展（用于与 OpenCode Server 通信）
    implementation("com.squareup.okhttp3:okhttp:4.12.0")
    implementation("com.squareup.okhttp3:okhttp-sse:4.12.0")
    
    // JSON 处理（用于解析 OpenCode 的 REST/SSE 响应）
    implementation("com.google.code.gson:gson:2.11.0")
    
    // Markdown 转 HTML（用于 JBHtmlPane 渲染）
    implementation("org.jetbrains:markdown:0.7.3")
}
```

`okhttp-sse` 是 OkHttp 官方的 SSE 扩展库，提供了 `EventSource` 和 `EventSources` 类，可以像浏览器端一样监听 SSE 事件流。

### 3.3 Kotlin 配置

如果使用 Kotlin 开发（推荐），确保应用 Kotlin JVM 插件：

```kotlin
plugins {
    id("org.jetbrains.kotlin.jvm") version "2.1.0"
}
```


## 四、插件开发核心概念

### 4.1 plugin.xml：插件注册入口

`plugin.xml` 是插件的声明式配置文件，位于 `src/main/resources/META-INF/` 下。OpenCode 插件需要注册以下扩展点：

```xml
<idea-plugin>
    <id>com.yourcompany.opencode.plugin</id>
    <name>OpenCode AI Assistant</name>
    <vendor>Your Company</vendor>

    <!-- 依赖项 -->
    <depends>com.intellij.modules.platform</depends>
    <depends>com.intellij.modules.lang</depends>

    <!-- 注册 Tool Window -->
    <extensions defaultExtensionNs="com.intellij">
        <toolWindow id="OpenCode"
                    anchor="right"
                    factoryClass="com.yourcompany.opencode.frontend.AgentToolWindowFactory"
                    icon="/icons/opencode.svg"/>
    </extensions>

    <!-- 注册右键菜单 Action（添加上下文） -->
    <actions>
        <action id="OpenCode.AddToContext"
                class="com.yourcompany.opencode.frontend.actions.AddToContextAction"
                text="Add to OpenCode Context">
            <add-to-group group-id="EditorPopupMenu" anchor="last"/>
        </action>
    </actions>
</idea-plugin>
```

`ToolWindowFactory` 是 Tool Window 的入口类，你需要实现 `createToolWindowContent(Project, ToolWindow)` 方法，在其中将 Swing 面板添加到 Tool Window 中。

### 4.2 Tool Window 实现骨架

```kotlin
class AgentToolWindowFactory : ToolWindowFactory {
    override fun createToolWindowContent(project: Project, toolWindow: ToolWindow) {
        val panel = OpenCodeMainPanel(project)  // 你的 Swing 面板
        val content = ContentFactory.getInstance().createContent(panel, "", false)
        toolWindow.contentManager.addContent(content)
    }
}
```

`OpenCodeMainPanel` 是一个继承自 `JPanel` 的类，内部用 `JBSplitter` 分为会话列表（左）和对话面板（右），对话面板中嵌入 `JBScrollPane` 包裹的消息列表。


## 五、核心 API 使用要点

### 5.1 子进程管理（启动 OpenCode Server）

使用 `OSProcessHandler` 管理 OpenCode Server 子进程：

```kotlin
val commandLine = GeneralCommandLine("opencode", "serve", "--port", port.toString())
val processHandler = OSProcessHandler(commandLine)
processHandler.startNotify()

// 在 dispose 中确保终止
override fun dispose() {
    processHandler.destroyProcess()
    processHandler.killProcessTree()  // 确保子进程树完全终止
}
```

**注意**：2026.2 版本禁止在 EDT 线程上调用 `OSProcessHandler.waitFor()`，否则会记录错误日志。Server 就绪检测应在后台线程中通过轮询健康检查接口完成。

### 5.2 SSE 事件监听

使用 `okhttp-sse` 的 `EventSource` 监听 OpenCode 的事件流：

```kotlin
val request = Request.Builder()
    .url("http://localhost:$port/global/event")
    .build()

val eventSource = EventSources.createFactory(okHttpClient)
    .newEventSource(request, object : EventSourceListener() {
        override fun onEvent(eventSource: EventSource, id: String?, type: String?, data: String) {
            // 解析事件，通过 SwingUtilities.invokeLater 更新 UI
        }
    })
```

SSE 连接必须在后台线程中建立，事件解析后通过 `ApplicationManager.getApplication().executeOnPooledThread()` 和 `SwingUtilities.invokeLater()` 将 UI 更新调度到 EDT 线程。

### 5.3 流式渲染的批量刷新

使用 `javax.swing.Timer` 实现 75ms 间隔的批量刷新，避免每个 token 触发一次 EDT 更新：

```kotlin
val flushTimer = Timer(75) {
    // 从缓冲区读取累积的文本，批量更新 UI 组件
}
flushTimer.start()
```

IntelliJ 平台也提供了 `DebouncedUpdates` 工具类作为替代方案。


## 六、运行与调试

### 6.1 运行插件

在 Gradle 面板中执行 `runIde` 任务，或直接在 IDE 右上角选择 `Run Plugin` 配置。这会启动一个**沙箱 IDE**（Sandbox IDE），其中自动安装了你正在开发的插件，你可以在沙箱中测试插件的所有功能。

### 6.2 日志查看

调试时**不要只看 Gradle 输出**。更有效的做法是直接查看沙箱 IDE 的 `idea.log` 文件：

- 沙箱日志默认位于 `build/idea-sandbox/system/log/idea.log`
- 建议将沙箱数据目录移到 `build/` 之外，避免 `gradle clean` 时被删除
- 在 `build.gradle.kts` 中配置日志级别，将你的插件日志设为 DEBUG，其余设为 WARN，便于过滤

### 6.3 断点调试

在插件代码中设置断点，然后以 Debug 模式运行 `runIde` 任务。沙箱 IDE 启动后，当代码执行到断点处会暂停，你可以像调试普通应用一样检查变量和调用栈。

### 6.4 建议：自定义 runIde 任务

一个实用的技巧是**不要直接运行 `gradle runIde`**，而是继承 `runIde` 注册一个自定义任务，因为 `runIde` 会忽略部分参数：

```kotlin
val runIdeDebug by intellijPlatformTesting.runIde.registering {
    // 自定义 JVM 参数、日志路径等
}
```


## 七、打包与安装

### 7.1 构建插件包

执行 Gradle 任务 `buildPlugin`，生成的插件包位于 `build/distributions/` 目录下。

### 7.2 本地安装测试

在目标 IDE 中，`Settings` → `Plugins` → 齿轮图标 → `Install Plugin from Disk`，选择生成的 `.zip` 文件即可。


## 八、项目结构总览

完成以上步骤后，你的 OpenCode 插件项目结构应如下：

```
opencode-idea-plugin/
├── build.gradle.kts
├── gradle.properties
├── settings.gradle.kts
├── shared/
│   └── src/main/kotlin/
│       └── com/yourcompany/opencode/shared/
│           ├── dto/            # 事件 DTO、消息模型
│           └── rpc/            # RPC 接口契约
├── frontend/
│   └── src/main/
│       ├── kotlin/
│       │   └── com/yourcompany/opencode/frontend/
│       │       ├── AgentToolWindowFactory.kt
│       │       ├── panel/      # Swing 面板组件
│       │       ├── viewmodel/  # ViewModel
│       │       └── actions/    # 右键菜单 Action
│       └── resources/
│           └── META-INF/
│               └── frontend.xml
└── backend/
    └── src/main/
        ├── kotlin/
        │   └── com/yourcompany/opencode/backend/
        │       ├── server/     # OpenCode Server 进程管理
        │       ├── client/     # REST + SSE 客户端
        │       └── model/      # 消息状态管理
        └── resources/
            └── META-INF/
                └── backend.xml
```

**建议**：即使你选择从普通 New Project 向导开始，也尽量在第一天就建立 `shared` / `frontend` / `backend` 的模块划分。这为第二阶段复用状态管理逻辑奠定了基础，避免后期大规模重构。
